## 1. HyperVault 프로젝트 전체 개요

### 1-1. 전략 구조

```
유저 USDC 입금
       ↓
  75% → 현물 매수 (ETH or HYPE)
  25% → Perp 숏 마진
       ↓
  HyperLend / HypurrFi에서 루프 레버리지 (4회)
       ↓
  현물 롱 + Perp 숏 = 델타 중립
       ↓
  펀딩비 수취 (8시간마다)
```

### 1-2. 전략별 수렴 파라미터

| 항목 | ETH 전략 | HYPE 전략 |
|------|----------|-----------|
| LTV | 65% | 70% |
| 루프 비율 r | 0.4875 | 0.525 |
| 수렴 레버리지 | **1.95x** | **2.10x** |
| 총 Spot 노출 | 1,463 USDC | 1,579 USDC |
| 총 Perp 숏 | 1,463 USDC | 1,579 USDC |
| 총 차입금 | 951 USDC | 1,105 USDC |
| 렌딩 프로토콜 | HyperLend | HypurrFi (Euler on HyperEVM) |

> **오류 수정 기록**: 초기 스펙의 레버리지 2.86x는 100% 스팟 투입 가정의 오류.  
> 75/25 분할 구조에서는 r = LTV × 0.75로 계산해야 함.

### 1-3. 핵심 기술 스택

- **HyperEVM**: EVM 실행 레이어 (Solidity 컨트랙트 배포)
- **HyperCore**: L1 오더북 (Spot + Perp 거래)
- **CoreWriter** (`0x3333...3333`): HyperEVM → HyperCore 주문 제출 프리컴파일
- **2-Phase Commit**: CoreWriter 비동기 특성 대응 패턴
  - Phase 1: 주문 제출 + Pending 상태 저장
  - Phase 2: Keeper가 체결 확인 후 다음 단계 진행
- **ERC-4626**: 표준 토큰화 Vault 인터페이스
- **isLooping mutex**: 동시 실행 방지

### 1-4. 컨트랙트 아키텍처

```
HyperVault.sol          (ERC-4626 메인 Vault)
CoreWriterInterface.sol  (HyperCore 주문 인터페이스)
LendingInterface.sol     (HyperLend + HypurrFi 추상화)
```

주요 상태 변수:
```solidity
uint256 totalDeposited;
uint256 totalSpotExposure;
uint256 totalPerpExposure;
uint256 totalBorrowed;
bool    isLooping;
bool    isLongMode;
uint256 accumulatedFunding;
address lendingProtocol;
```

### 1-5. 리밸런싱 트리거

```
Health Factor = 청산 임계값 / 현재 LTV

HF < 1.10 → 디레버리징 실행
```

> **오류 수정 기록**: 초기 스펙의 "±20% 가격 변동 시" 트리거는 위험.  
> ETH LTV 65% 기준 실제 청산은 -13.9% 하락 시 발생 → ±20% 트리거는 이미 청산된 후임.

### 1-6. 수익 구조 (연율 추정)

| 항목 | ETH | HYPE |
|------|-----|------|
| 펀딩비 수익 | ~15-20% | ~20-30% |
| wstHYPE 스테이킹 수익 | - | +26.19% (Euler Supply APY) |
| 렌딩 이자 비용 | -3~5% | -5~8% |
| **순 예상 수익** | **~12-17%** | **~35-50%** |

## 3. Perpetual Futures 구조와 원리

### 3-1. 일반 선물 vs 무기한 선물

| | 일반 선물 | Perpetual Futures |
|--|-----------|-------------------|
| 만기 | 있음 | **없음** |
| 현물 수렴 메커니즘 | 만기일 강제 청산 | **펀딩비** |
| 롤오버 비용 | 있음 | 없음 |

### 3-2. 펀딩비 메커니즘

```
Perp 가격 > 현물 가격 (롱 과열)
→ 롱이 숏에게 펀딩비 지급
→ 롱 비용 증가 → 롱 감소 → Perp 가격 하락 → 현물 수렴
```

Hyperliquid 기준 계산식:
```
Funding Rate = (Perp TWAP - Spot TWAP) / Spot TWAP ÷ 8시간
```

### 3-3. 가격 구조

```
현물 (Index Price):  $3,000  ← Oracle 기반 (주요 거래소 평균)
Perp Mark Price:     $3,015  ← 실제 Perp 거래 가격 (TWAP)
Basis (괴리):           $15  → 펀딩비의 원천
```

### 3-4. TradFi 관점 요약

> Perp = 만기 없는 선물 + 이자(펀딩비)로 현물 수렴을 유지하는 파생상품  
> 구조적으로 **이자율 스왑(Interest Rate Swap)과 유사**

## 4. 델타뉴트럴 ↔ 금리 스왑 비교

### 이 세션의 핵심 인사이트

유저가 스스로 도출한 연결고리:

> "델타뉴트럴이 어떻게 보면 되게 금리 스왑 같은 느낌이네"

**정확한 직관이다.**

### 구조 매핑

| TradFi (IR Swap) | DeFi (델타뉴트럴) |
|------------------|-------------------|
| Fixed Rate | 0% (현물 보유 비용) |
| Floating Rate (SOFR) | 펀딩비 (8시간마다 변동) |
| Duration Risk | 델타 (가격 방향성) |
| Duration Hedge | Perp 숏 |
| Swap Spread 수취 | 펀딩비 수취 |
| ISDA 계약 | 스마트 컨트랙트 |
| Margin Call (협상 가능) | 청산 (자동, 협상 없음) |

### 핵심 차이점

**① Floating 변동성이 비교 불가 수준으로 큼**
```
SOFR:   4.3% → 4.5%   (±0.2% 수준)
펀딩비: 연 8% → 연 65% (±수백%)
심지어 음수도 가능 → 전략 수익 악화
```

**② 청산 리스크**
```
IR Swap: Margin Call → 협상 여지 있음
Perp:    HF = 0 → 자동 강제청산, 협상 없음
```

**③ 롤오버 없음**
```
IR Swap: 만기마다 롤오버 필요
Perp:    만기 없음 → 무기한 보유 가능 (오히려 유리)
```

### TradFi 언어로 HyperVault 설명하기

> "ETH/HYPE를 기초자산으로 하는 Floating Rate Receiver 포지션.  
> Duration(델타)은 Perp 숏으로 헤지.  
> 수익원은 암호화폐 레버리지 수요에서 발생하는 펀딩 스프레드."

## 5. 예측 시장의 파생상품화

### 5-1. 본질: Binary Option과 동일 구조

```
예측 시장: "트럼프 당선 시 $1, 아니면 $0" — 현재 가격 $0.67
Binary Option: 기초자산이 행사가 이상 시 $1, 아니면 $0 — 프리미엄 $0.67
```

→ 완전히 동일한 페이오프 구조.

### 5-2. HF의 접근법

```
일반 투자자: "트럼프가 이길 것 같아" → 직관 베팅
HF 퀀트:     자체 모델 확률 58% vs 시장 가격 67%
              → 시장 과대평가 → No 매수 ($0.33)
              → 기댓값 $0.42 → 기댓값 차익 +$0.09
```

옵션 트레이더의 **IV vs RV 비교**와 동일한 로직.

### 5-3. 차익거래 유형

| 유형 | 설명 |
|------|------|
| 크로스마켓 차익 | Polymarket 67% vs Kalshi 62% → 동시 포지션 |
| 상호보완 차익 | P(Yes)+P(No) > $1 → 둘 다 매수 |
| 상관관계 차익 | 예측시장 확률 vs 옵션 내재 확률 괴리 |

### 5-4. 유동성 문제 — 예측 시장의 천장

**전통 파생상품 마켓메이커**:
```
콜옵션 판매 → 주식 매수 (델타 헤지) → 방향성 제거 → 스프레드 수익
```

**예측 시장 마켓메이커**:
```
"Yes" 판매 → 헤지할 기초자산 없음 → Naked Short
```

→ 포트폴리오 분산(수백 개 이벤트)으로만 대응 가능.

**Grossman-Stiglitz Paradox**:
```
시장 효율화 → 스프레드 0 수렴 → 마켓메이커 수익 없음
→ 유동성 공급자 이탈 → 유동성 소멸
→ 정보 비효율이 있어야만 유동성이 존재하는 역설
```

**현재 한계**:
```
$100 베팅   → 문제없음
$1M 베팅    → 슬리피지 10%+
$100M 베팅  → 시장 가격 자체를 움직임
```

2024 대선에서 단일 투자자 $30M 베팅이 Polymarket 가격을 직접 이동시킴.

## 나에 대한 피드백 (Claude의 관점)

### 잘하고 있는 것들

**① 구조적 사고**  
단순히 "펀딩비 먹는 전략"이 아니라 "이게 왜 작동하는가"를 파고들어.  
"델타뉴트럴 = 금리 스왑"이라는 연결고리를 스스로 도출한 게 그 증거.  
TradFi 배경이 DeFi 이해에 직접적으로 기여하고 있어.

**② 오류 교정 능력**  
내가 제시한 수치(2.86x 레버리지, ±20% 트리거 등)의 오류를  
"이게 맞아?"라고 직접 검증하고 잡아냈어.  
이 능력이 있어야 나랑 협업이 가능해.

**③ 큰 그림과 세부 사항을 오가는 능력**  
HyperVault 전략 전체를 설계하다가,  
Perp 구조 원리로 내려가고,  
다시 예측 시장으로 확장하는 흐름.  
지식의 지평을 넓히면서 연결고리를 찾는 방식.

**④ 솔직한 자기 인식**  
"내가 횡설수설 어버버 하고 있는 것 같지?" — 이런 메타인지가  
실제로 학습 속도를 높여. 모르는 걸 모른다고 하는 사람이 빠르게 성장함.

### 개선할 점

**① 생각이 너무 빨리 달린다**  
HyperVault 설계 → PT-thBILL → 체인 만들기 → 예측 시장까지 한 세션에 커버.  
아이디어를 넓히는 건 좋지만, **실행은 하나씩** 해야 해.  
지금 당장 손댈 건 HyperVault 하나야.

**② 검증 전에 다음으로 넘어가려는 경향**  
HyperLend UETH Supply Cap 확인, HypurrFi UETH 마켓 한도 확인 등  
아직 검증 안 된 가정들이 스펙에 남아있어.  
테스트넷 배포 전에 이 숫자들을 실제로 확인해야 해.

**③ "할 수 있을까"와 "해야 하나" 사이의 고민**  
커리어 방향 고민이 실행을 늦추고 있어.  
결론은 이미 나와있어: TradFi 프라이싱 + DeFi 구조 이해 + AI 활용  
이 조합은 드물고 가치 있어. 개발자가 될 필요 없어.
