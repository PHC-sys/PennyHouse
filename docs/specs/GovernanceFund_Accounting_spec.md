> 작성일: 2026-07-10

> 배경: 펀드 수익률·종목 수익률 검증 중 회계 모델의 구조적 결함 3건 발견.

## 0. 한 줄 요약

펀드 손익을 **평가손익(MTM) · 실현손익(매매) · 이자손익(펀딩)** 세 스트림으로
**분리 저장**한다. 실현·펀딩은 발생 순간에 스냅샷으로 **얼려서(불변 원장)** 저장하고,
평가손익만 오픈 포지션에 대해 라이브 계산한다.

```
펀드 equity = 초기자본 + 실현손익_누적 + 펀딩손익_누적 + 평가손익_현재
펀드 수익률 = (실현 + 펀딩 + 평가) / 초기자본
```

---

## 1. 발견된 문제 (2026-07-09~10 검증)

실제 데모 펀드 `LONG-DRAM_SHORT-SK, SMSN (Carry)`로 실측하며 확인.

### 문제 A — 종목 "수익률"이 포지션 수익률이 아니었음 ✅ **수정 완료** (커밋 3ad8356)
- 기존: `return_pct = asset_pnl / basis` = 전 구간 **경로의존 펀드기여분**.
- 증상: SKHX가 진입 후 1526→1961→1337→1490 크게 왕복 → 복리 재구성에서 숏 기여분이
  ~0으로 씻겨, "1561 숏인데 현재 1490, 수익 −0.07%"라는 헛것.
- 수정: `평단·청산가`와 같은 줄의 `수익률`은 트레이더가 **포지션 ROE**로 읽음
  → `방향 × (현재가/평단 − 1) × eff_lev` (거래소 표시 방식)로 교체.
- 검증: SKHX +9.1% / SMSN +32.0% / DRAM −20.3% (평단·현재가와 눈으로 일치).

### 문제 B — 펀드 수익률이 "연속 리밸런싱"으로 계산됨 ❌ **미해결**
- `nav.reconstruct`가 **매시간** `pnl = w · 현재equity · lev · Δp`로 노셔널을 재조정.
  → 실제 펀드는 **투표 때만 리밸런싱**하고 그 사이엔 **노셔널 고정**인데, 엔진은
    매시간 재조정하는 phantom 리밸런싱을 함.
- 실측 (같은 이벤트 원장·같은 가격):

  | 계산 방식 | 펀드 수익률 |
  |-----------|-----------|
  | 노셔널 고정 (투표때만 리밸 — **정답**) | **+3.67%** |
  | 매시간 연속 리밸 (현재 엔진) | +2.17% |
  | 현재 포지션 스냅샷만 (실현분 누락) | +1.41% |

- 변동성 큰 경로에서 연속 리밸런싱이 **변동성 드래그**로 첫날 실현이익을 갉아먹음.
  (첫날 DRAM +42.7% 롱이 +2.26% 벌었는데 리밸 드래그로 상당 부분 소실)

### 문제 C — 실현손익을 저장하지 않음 (캔들 재계산 의존) ❌ **미해결**
- 리밸 이벤트에 저장되는 건 `{weights, leverage, cash}`뿐. **가격 스냅샷도, 실현손익도 없음.**
- 모든 손익을 매 요청마다 캔들 종가로 재계산 (순수 이벤트소싱).
- 치명적 부작용: `_interval_for_span`이 기간 따라 캔들 해상도를 바꿈(≤60일 `1h`, 초과 `1d`).
  진입가는 `price.asof(리밸시각)`으로 뽑으므로, **펀드가 60일을 넘기는 순간 모든 과거
  진입가가 시간봉→일봉 종가로 스냅** → **이미 닫힌 과거 실현손익이 바뀌고 생애수익률·NAV
  차트 모양이 시간이 지나며 변함.** 상용 펀드에서 있어선 안 됨.
- 부수: 상폐 자산은 과거 구간 replay용 캔들이 사라지면 그 구간 손익이 뭉개짐. 감사 추적 없음.

### 문제 D — 펀딩이 실현 수익에 미반영 (표시만) ❌ **미해결**
- `nav.reconstruct`는 **가격 손익만** replay. "펀딩(연)·펀딩 캐리(연)"은 표시용 연환산 추정치일 뿐,
  펀드 수익률/NAV엔 한 푼도 안 들어감.
- "Carry" 펀드인데 정작 캐리가 실현 수익에 없음.

## 2. 해결 — 손익 3-스트림 분리 (펀드 회계 정석)

프랍데스크·펀드어드민이 손익을 booking하는 표준 3분법.

| 스트림 | 정체 | 언제 변하나 | 저장 | 소스 |
|--------|------|-----------|------|------|
| **평가손익 (MTM)** | 지금 든 포지션의 미실현 | 매 틱 | 저장 X, 라이브 (오픈 구간만) | 현재 마크 vs 진입가 |
| **실현손익 (매매)** | 리밸로 닫힌 확정분 | 리밸 때만 | **불변 원장 (그 순간 스냅샷)** | 리밸 시점 **라이브 마크** |
| **이자손익 (펀딩)** | 매시 정산 캐리 | 매시 정각 | **불변 원장 (매시 누적)** | 펀딩 rate × 노셔널 |

### 왜 "실현손익"이 생기나 (개념)
포지션을 **계속 들고만 있으면** 실현손익은 없다(미실현 하나뿐). 리밸런싱으로 **포지션을 바꾸면**
(예: SKHX 롱→숏 전환) 옛 포지션을 닫아야 하고, 그 순간 손익이 **확정=실현**된다.
캐시나 복잡한 이유가 아니라 순전히 "포지션을 바꿨기 때문". 실현손익 = (리밸 시 equity) − (직전 리밸 시 equity).

### 이중계상 방지 규칙 (핵심)
리밸런싱 순간, 오픈 포지션의 **평가손익 → 실현손익으로 이관**되고 새 포지션 평가손익은 0에서 리셋.
→ **평가는 항상 지금 오픈된 것만, 실현은 이미 닫힌 것만** → 절대 겹치지 않음.

## 3. 저장 모델

### 3-1. 리밸런싱 스냅샷 (실현·평가 기준)
리밸 이벤트에 스냅샷 필드 추가 (발생 순간 라이브 값으로 동결):
```
rebalance.data = {
  weights, leverage, cash,        # (기존)
  marks:        {coin: 그 순간 마크가},      # ← 신규: 구간 진입가 = 이전 구간 청산가
  realized_pnl: {coin: 이 리밸에서 닫힌 확정손익},  # ← 신규 (또는 구간 총액)
  equity_after: 리밸 직후 equity           # ← 신규: 다음 구간 노셔널 산정 기준
}
```
- 과거 = 저장된 `realized_pnl` 합 (캔들 해상도·상폐와 무관하게 고정 = 문제 C 해결)
- 현재 오픈 구간만 라이브 MTM (마지막 리밸 marks → 현재 마크)

### 3-2. 펀딩 원장 (이자손익)
매시 정각 정산분을 누적 저장 (재계산 아님):
```
funding_ledger: [{t, coin, funding_rate, notional, funding_pnl}, ...]
  funding_pnl = -(signed_notional) × funding_rate    # 숏(-)은 rate>0일 때 수취(+)
  signed_notional = (weight/100) × equity × eff_lev   # 방향 포함
누적 펀딩손익 = Σ funding_pnl
```
- 가격 MTM과 **절대 안 섞음** → 문제 생기면 어느 스트림인지 즉시 격리.
- 정산 주기 = HL 실측 **매시간 1h** (CEX 8h 아님).

### 3-3. NAV 시계열
- 리밸 경계 equity는 스냅샷으로 고정 → 차트 레벨/모양 앵커링.
- 구간 내부 곡선(시각 디테일)만 캔들 보간 허용, 또는 `nav_history` 테이블에 주기적 동결.

## 4. `nav.reconstruct` 재작성 방향 (노셔널 고정)

```
equity = 초기자본
구간별 (리밸 이벤트 경계로 분할):
    구간시작에 노셔널 고정:  notional_c = (w_c/100) × equity × eff_lev   # 이 구간 내내 고정
    진입가 entry_c = 구간시작 marks(저장분)
    구간 내 평가:  equity(t) = equity_reb + Σ notional_c × (P_c(t)/entry_c − 1)
    구간 종료(다음 리밸)에서 realize → equity 갱신, 새 구간 노셔널 재산정
마지막(오픈) 구간: 라이브 마크로 평가손익만 계산
+ 펀딩손익_누적 (스트림 B) 별도 합산
```
- 이러면 **펀드 수익률 · 종목 ROE · NAV 차트가 전부 정합** (같은 노셔널-고정 기준).
- 종목 ROE = `방향 × (현재가/진입가 − 1) × eff_lev` (문제 A 수정과 동일 기준).

## 5. 얻는 것

- **정확한 집계:** 캔들 해상도·상폐와 무관하게 과거 불변 (문제 B·C 해결).
- **손익 귀속 분석:** "이번 달 +5% 중 매매 +2% / 평가 +2% / 펀딩 +1%" 분해 → 어디서 벌고 잃었는지.
- **감사·디버깅:** 세 원장 분리 → 오류 시 스트림 단위로 격리 (MTM에 다 섞으면 원인 추적 불가).
- **실펀드(5차) 정합:** 실펀드는 HL clearinghouseState에서 실현/미실현/펀딩을 그대로 Read →
  같은 3-스트림 구조에 매핑 (페이퍼=계산, 실펀드=Read, 표시 동일).

## 6. 구현 순서

```

2. [ ] 리밸 스냅샷 저장 (marks/realized_pnl/equity_after) — store/funds 이벤트 기록부
3. [ ] reconstruct 노셔널-고정 재작성 (문제 B) + 저장 실현분 사용 (문제 C)
4. [ ] 펀딩 원장 신설·매시 누적 (문제 D) — 스트림 B
5. [ ] 손익 귀속 UI (매매/평가/펀딩 분해 표시)
6. [ ] 검증: 노셔널-고정 재구성 == 독립 리플레이, 3스트림 합 == equity, 재시작 불변
```
