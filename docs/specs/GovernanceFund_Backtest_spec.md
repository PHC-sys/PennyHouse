# GovernanceFund 백테스팅 & 페이퍼 트레이딩 사이트 스펙

> 작성일: 2026-06-10
> 상태: 설계 중 (v0.1)
> 분류: GovernanceFund 부속 도구 (테스트넷/데모 레이어)

---

## 1. 목적

GovernanceFund의 **투표 → 운용 메커니즘을 돈 없이 체험·검증**하는 사이트.

두 가지 모드:
1. **과거 백테스트** — 투표 시나리오를 과거 데이터에 적용 → 수익률 확인
2. **라이브 페이퍼 트레이딩** — 실시간으로 투표만 하고 실제 자금 없이 펀드 수익률 추적

**중요**: 본 플랫폼 정식 출시 후에도 **영구적인 테스트넷/데모 페이지**로 유지.
신규 참여자가 돈 넣기 전에 "투표가 어떻게 운용으로 이어지는지" 학습하는 온보딩 도구.

---

## 2. 왜 필요한가

| 대상 | 가치 |
|------|------|
| 신규 참여자 | 돈 넣기 전 메커니즘 체험 (온보딩) |
| 기존 참여자 | 전략 아이디어를 실투입 전 검증 |
| 운영자 | 파라미터(ALPHA, 레버리지) 튜닝 근거 확보 |
| 외부 관찰자 | 펀드 투명성 — "이런 식으로 굴러간다" 공개 |

핵심: **"투표 품질이 수익을 결정한다"**는 걸 직접 만져보게 하는 것.
(02번 백테스트의 결론을 인터랙티브하게)

## 3. 모드 1 — 과거 백테스트

### 입력
```
- 기간 선택 (최근 30/90/180일, 또는 커스텀)
- 코인 유니버스 (BTC/ETH/SOL/HYPE/...)
- 펀드 프로파일 (공격적/보수적, 또는 ALPHA·레버리지 직접 조절)
- 투표 시나리오:
    · 프리셋 (모멘텀 / 역추세 / 랜덤 / 완벽예측)
    · 또는 사용자가 주차별 투표 직접 입력
```

### 출력
```
- 누적 수익률 곡선 (vs Buy&Hold)
- 최대 낙폭(Drawdown)
- 성과 지표 (연환산 수익률, Sharpe, Calmar, 승률)
- 주차별 포트폴리오 비중 변화 (롱/숏 시각화)
- 청산 발생 여부
```

### 엔진
```
backtest/GovernanceFund_weight_decision/02_backtest_scenarios.ipynb
→ 핵심 함수(votes_to_target, run_backtest)를 그대로 API화
```

## 4. 모드 2 — 라이브 페이퍼 트레이딩

### 개념
```
실제 돈 없이 가상 예치금 부여 → 매주 투표 → AI/시스템이 실제 HL 가격으로
가상 포지션 운용 → 실시간 수익률 추적
```

### 흐름
```
1. 참여자: 가상 예치금 받음 (예: $10,000 paper)
2. 매주 투표 라운드:
     - 코인별 방향 투표 (-2 ~ +2, Kahoot 스타일)
     - 예치금 가중 집계 (simulate_votes)
3. 시스템: votes_to_target → 목표 비중 산출
4. 실시간 가격(HL API)으로 가상 포지션 평가
5. 대시보드: 내 지분 / 펀드 전체 수익률 실시간 표시
```

### 실제 펀드와의 차이
| | 페이퍼 (이 사이트) | 실제 GovernanceFund |
|--|------------------|---------------------|
| 자금 | 가상 | 실제 USDC |
| 주문 | 가상 (가격만 참조) | HL 실제 주문 |
| 청산 | 시뮬레이션 | 실제 청산 |
| 목적 | 학습·검증 | 운용 |
| 메커니즘 | **동일** | **동일** |

→ 메커니즘이 동일하므로, 페이퍼에서 익힌 그대로 실제로 넘어갈 수 있음.

## 5. 아키텍처

```
[프론트엔드 — Next.js]
  과거 백테스트 페이지
  라이브 페이퍼 트레이딩 페이지
  공통 차트 컴포넌트 (lightweight-charts)
        ↓ REST
[백엔드 — Python FastAPI]
  /backtest        과거 시나리오 실행 (02번 엔진)
  /paper/vote      페이퍼 투표 제출
  /paper/portfolio 현재 가상 포트폴리오 조회
  /paper/nav       실시간 수익률 (NAV) 계산
  /prices          HL candle/price 프록시 (캐싱)
        ↓
[데이터]
  HL API (가격)
  DB (페이퍼 투표/포지션 상태) — 초기 SQLite, 이후 Postgres
        ↓
[스케줄러]
  주간 투표 마감 → votes_to_target → 가상 리밸런싱
  (GitHub Actions cron 또는 Render cron)
```

### 02번 노트북 재사용
```python
# 노트북 핵심 함수를 모듈로 추출
governance_engine/
  voting.py      simulate_votes, votes_to_target
  backtest.py    run_backtest, calc_metrics
  prices.py      fetch_candles (HL API)
  profiles.py    FUND_PROFILES, VOLATILITY
```
→ FastAPI는 이 모듈을 import만 하면 됨.

## 6. 화면 구성 (MVP)

### 페이지 1: 과거 백테스트
```
[설정 패널]  기간 · 코인 · 프로파일 · 시나리오
[실행 버튼]
[결과]  수익률 곡선 / 지표 카드 / 비중 변화 차트
```

### 페이지 2: 라이브 페이퍼 트레이딩
```
[내 현황]  가상 예치금 · 지분율 · 현재 수익률
[투표 패널]  코인별 방향 슬라이더 (마감 타이머)
[펀드 현황]  포트폴리오 파이 / 실시간 NAV 곡선
[리더보드]  (선택) 페이퍼 참여자 수익률 랭킹
```

### 페이지 3: 메커니즘 설명 (온보딩)
```
- 투표가 어떻게 비중이 되는가 (votes_to_target 시각화)
- 예치금 가중치 설명
- Target 방식 인터랙티브 데모
```

## 7. 랭킹 시스템 연결점

이전 논의된 "펀드별 랭킹 시스템"의 출발점이 될 수 있음:
```
페이퍼 참여자별 수익률 → 리더보드
→ 정식 펀드 출시 후 실제 펀드 랭킹으로 확장
→ 반투명 공개 (기초자산 + 누적 수익률만)
```

단, copy-trading 유도는 규제 고려해 별도 검토 (DeFi 한정).

## 8. 미확정 사항

| 항목 | 옵션 | 메모 |
|------|------|------|
| 페이퍼 예치금 부여 방식 | 가입 시 고정 / 지갑 연결 시 | 초기 고정 $10k |
| 투표 주기 | 실시간 / 주간 고정 | 주간 (실제 펀드와 동일) |
| 리더보드 공개 범위 | 익명 / 닉네임 / 지갑 | 닉네임 |
| DB | SQLite / Postgres | MVP는 SQLite |
| 인증 | 지갑 서명 / 이메일 | 지갑 서명 |
| 배포 | Render (기존) | 백엔드+프론트 분리 배포 |
