# 2026-06-15 (오후) — NAV 재구성: 메모리 누적 폐기, 이벤트 소싱 전환

> "취미가 아니라 비즈니스가 될 플랫폼" — 정석대로. 토이와 비즈니스를 가르는 선:
> 파생값을 저장하느냐, 입력만 저장하고 매번 계산하느냐.

## 왜 했나 (한 뿌리의 버그들)
mid/mark 오평가, 재시작 리셋, NAV 절벽, HIP-3 손익 동결 — 전부 독립 버그가 아니라
**하나의 병**: "파생 상태(equity/손익)를 실시간 피드로 메모리에서 누적"한 것. 누적식이라
어떤 피드를 보냐·언제 재시작하냐·어떤 틱을 봤냐에 따라 흔들렸다(비결정적).

## 무엇으로 바꿨나
**이벤트 소싱 + 결정론적 투영.**
- 진실의 원천 = 불변 이벤트 원장 `store.fund_events`
  · `rebalance`{weights,leverage,cash} : 비중 바뀔 때(투표/회수 후)
  · `redeem`{keep} : 참가자 출금 (keep=1−share)
- NAV/equity/손익 = 원장 + HL 정규 캔들가격을 replay한 **순수 함수** `api/nav.reconstruct`
  · equity = initial × Π[구간](1+Σ w·eff_lev·(p_end/p_start−1)) × Π[회수] keep
  · 과거 = 캔들 종가(정규), 현재 점 = 라이브 markPx(진행 봉만 보정)
  · 회수: equity·basis·손익 동시 keep 축소 → 남은 참가자 수익률 불변
- `_runtime` = 현재 비중/정산 표시용 캐시(진실 아님). nav_history 미사용(직접 산출).

## 효과 (검증)
- **재시작 불변**: 서버 kill→재시작(메모리 0) 후 equity 0.02~0.06% 차이뿐(=재시작 몇 초
  실제 가격변동). 100k 리셋 없음. → "수정하면 펀드 사라진다" 구조적으로 소멸.
- **결정론**: 같은 state 두 번 호출 → 과거 시계열 완전 동일.
- **신규 펀드**: t0 asof 처리로 즉시 평단·현재 equity 표시.
- **회수**: a 출금→b 가치 보존(라이브 드리프트 내).
- 사용자 실제 11개 펀드 전부 백필로 무에러 재구성(투표 있으면 곡선, 없으면 평탄).
- 엔진 테스트 9/9 통과.

## 전환(cutover) 메모
- 기존 펀드는 첫 조회 시 created_at에 현재 비중으로 최초 rebalance 백필(구 스냅샷 비중
  우선). → 과거 NAV가 결정론적 재구성으로 한 번 바뀜(일회성, 이후 안정).
- 구 fund_runtime 누적 스냅샷은 백필 폴백으로만 잔존.

## 성능
- reconstruct 결과 4초 메모(_nav_cache) + 캔들 5분 캐시. iterrows 폴드는 추후 벡터화 여지.
